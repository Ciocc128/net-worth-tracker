# CLAUDE.md - Net Worth Tracker (Lean)

## Project Overview
Next.js app for Italian investors: net worth, assets, cashflow, dividends, performance metrics and long-term planning on Firebase.

**This file is the INDEX.** Detailed conventions, patterns and gotchas live in **AGENTS.md**; the aesthetic spec is **DESIGN.md**. Keep entries here to "what it is + where it lives".

> **Language**: this file and AGENTS.md are written in English. Italian is reserved for user-facing UI text (see AGENTS.md → *Italian Localization*). Page and feature names stay in Italian throughout, because they are the labels the product actually shows: Panoramica, Patrimonio, Cashflow, Analisi, Rendimenti, Allocazione, Storico, Previdenza, Impostazioni.

## Key Features (Active)
- **Shared account (delegated access)**: a second user gets full co-owner read/write. **viewer** (logged-in user) decoupled from **owner** (`ownerId`) via `useActiveAccount()`. Grants in `account-access/{ownerUid}`; enforcement in `firestore.rules` + `assertCanAccessAccount`. Theme stays per-viewer. Switcher in both `Sidebar` and `SecondaryMenuDrawer` (portrait has no sidebar). AGENTS.md → *Shared Account*.
- **Demo mode**: public landing `app/page.tsx` + auto-login; `useDemoMode()` gates every mutation. AGENTS.md → *Public Landing Page Hero*.
- **Panoramica (Overview)**: asymmetric bento hero `[2fr_1fr]` — dominant net worth + variation/ATH chip + sparkline with period selector + "Guidato da" digest, beside Sintesi Patrimoniale (with goal progress). Then Cashflow KPIs and deferred charts. `useDashboardOverview()` → `GET /api/dashboard/overview`. AGENTS.md → *Panoramica* + *Dashboard Data Isolation*.
- **Patrimonio (Portfolio)**: every asset type; hero twin of Panoramica; sortable table, 2-click delete, Δ columns behind "Andamento"; cash accounts in separate cards. Automatic prices (Yahoo / Borsa Italiana); `--chart-3` tint on manually-priced rows via `requiresManualPricing`.
- **AssetDialog**: 2-step create (type → filtered form), edit reuses the same visibility logic. For ledger types it shows qty/average cost read-only (submit via `updateAssetMetadata`). Class select for ETFs; optional `displayTicker` alias; `leverageRatio` for leveraged ETFs.
- **Asset trade ledger (Registro operazioni)**: BUY/SELL/ADJUSTMENT per asset with optional cash settlement (net-worth-neutral). `TransactionDialog` (+ capital-gain preview) and `AssetMovementsDialog` (P&L/return/XIRR). Writes only through the Admin API; the asset doc stays authoritative (full replay). Also feeds "Capitale investito"/"Plusvalenze" on Rendimenti and total return on Dividendi. AGENTS.md → *Asset Trade Ledger*.
- **Cashflow**: Tracciamento / Dividendi / Budget / (optional) Centri di Costo tabs. **Transfers** are a type of their own, net-zero everywhere, with atomic reconciliation of both balances. **Tracciamento** is single-answer IA: `CashflowHero` (net savings + one verdict + top-5 expenses) → filter toolbar → shared `TransactionFeed`. A saved entry's **type is editable across all five types** — cross-shape edits (transfer ↔ spesa/entrata) are reconciled from BOTH the old and new shape, while the batch re-typing paths (category type change, category/subcategory moves) refuse to cross the transfer boundary; the category re-attaches to the same-named one under the new type via `resolveEquivalentCategory`. AGENTS.md → *`ExpenseDialog` type change*.
- **Budget**: opt-in, overall ceiling + income budget + monthly|annual period, with Forecast / Insights / Alerts. Pure `lib/utils/budgetUtils.ts`.
- **Cost Centers**: optional 6th tab (`costCentersEnabled`); spending per project. **One period axis (Mese/Anno/12 mesi/Sempre) owned by the Panoramica and rendered in BOTH views** — the Detail used to display a period it could not change. Ordered list where the bar encodes rank and the `%` encodes share of the period total; per-center budget/projection/lifecycle; per-subcategory breakdown with session-only exclusions that never touch the figures above. Budget, projection and chart keep their **own** window and each names it in its eyebrow, behind a chapter separator. Dormancy reads **unscoped** activity (`resolveLastActivityDate`), so the badge no longer follows the axis; a center's colour is a **theme slot**, never a hex; `isError` routes to `CostCenterErrorNotice` *before* the empty-state check; delete declares how many expenses it unlinks. AGENTS.md → *Centri di Costo*.
- **Expense CSV Import**: Impostazioni → Spese. Pure parse/validate/plan layer with a mandatory preview before any write; shared `importBatchId` for one-tap undo. Category identity is **(name, type)** — same-named categories of different types resolve/create side by side, untyped rows inherit the single namesake's type (ambiguous → rejected with the reason), same-name-same-type duplicates attach to the OLDEST document with a notice in the preview. `transfer` rows are rejected and balances are never touched. AGENTS.md → *Expense CSV Import*.
- **Analisi** (`/dashboard/analisi`): period selector deep-linked in the querystring + KPI trio + anomalies + Sankey with `DrillBreadcrumb`; everything else behind a "Dettaglio" collapsible. **It is the only page with a Sankey**: "Anno Corrente / Anno / Storico" are not different views but a period selector on the same one. Categories and subcategories are keyed by **id** (never by name — same-named ones under different types are distinct documents) and labelled with the type only where they genuinely collide on screen. NOTE `cashflowHistoryStartYear` is shared (Cashflow/Storico/Assistant/overview) — do not rename it. AGENTS.md → *Analisi* + *Expense Grouping* + *Sankey: node identity*.
- **Dividendi (Dividends)**: Trade Republic-style IA with an in-memory period axis → net income hero + KPIs + reliability + payer leaderboard; Table/Calendar. `DividendStats` is a server-side YOC/DPS/total-return block, ledger-based (closed positions included with a "Chiusa" badge). **BTP Italia**: additive FOI coupon, the next one stays **provisional** until the user announces the rate.
- **Rendimenti (Performance)**: single-answer IA — `PerformanceHero` (dominant TWR + verdict + benchmark delta + drawdown chip + vital signs) → consistency strip → collapsible with the `MetricSection`s → charts clustered as "Andamento"/"Rischio". **Configurable basis** (pension funds and `excluded` assets are out by default), stated under the hero. **Drawdown on the TWR index**: Max Drawdown / Duration / Recovery / Underwater chain the same monthly returns as the heatmap. Window rules, IRR, thresholds and the Evoluzione chart: AGENTS.md → *Rendimenti: the measurement window*.
- **Benchmark comparison**: growth-of-100 + risk/return table over 6 model portfolios; Sharpe/Sortino against the period average of the ECB rate. **Env: `FRED_API_KEY`**.
- **Allocazione**: two-zone IA — Decision (`AllocationHero` + `RebalanceBandControl` + `ActionPlanner` Ribilancia/Versa/Preleva) then a "Dettaglio" divider → composition + exposure. **`Asset.allocationRole` (`tradable`|`frozen`|`excluded`) is partitioned BEFORE `compareAllocations`**: `frozen` stays in the denominator but never in a plan, `excluded` leaves the page entirely (which is why the total is smaller than net worth). **Leverage**: `leverageRatio` expands an asset into its notional exposure; the plans solve a QP per instrument. AGENTS.md → *Allocation*.
- **Storico (History)**: hero (net worth + CAGR) → Evoluzione → Raddoppi → Composizione (dedicated "Previdenza" band) → Driver. Includes **Valore per Strumento**: a per-instrument read of one month from `MonthlySnapshot.byAsset` (never recomputed) + cross-month trend with price/quantity attribution.
- **Fondo Pensione (Previdenza)**: manually-valued asset (`pensionFund`, value held in `quantity` at **price 1**), `allocationRole: 'frozen'` by default. Three chapters: *Il fondo oggi* (hero `[2fr_1fr]` + return, decomposition in a collapsible), *Anno fiscale {Y}* and *Storico {Y}*, the last two governed by a **year axis** (`SegmentedPill`) that never touches the value or the return. Contributions in three natures (TFR/Volontario/Datoriale); only Volontario leaves a cash account. **Multi-person**: each fund links to a `FamilyMember` (RAL + eligibility) and the tax recap runs **once per member**, with the IRPEF saving as the dominant number of its card. **Fund return**: market TWR kept separate from the employer contribution (pay, not return) and from the IRPEF saving; when the window is suspicious or idle **both the number and its decomposition are replaced by an explanation** — one predicate, `isPensionReturnMeasurable`, read by the card and by the collapsible's guard. The `[2fr_1fr]` hero always has a companion (return, error, or `PensionReturnPendingCard`), every chapter degrades to `PensionErrorNotice` instead of zeros, and the copy agrees in number when more than one fund exists (`fundNoun`). Integrated into Allocazione (look-through), Storico (band), Rendimenti (outside the basis) and FIRE (optional locked capital). AGENTS.md → *Fondo Pensione* + *Previdenza: audit follow-up*.
- **FIRE + Coast FIRE + What If + Monte Carlo**: FIRE Number with Bear/Base/Bull projection; Coast FIRE discounts the number to today with optional state pensions and editable IRPEF brackets; What If simulates life events by re-running `fireService` twice; Monte Carlo with a probability hero.
- **Goal-Based Investing**: trajectory-led (required monthly pace + projected date + verdict); optional goal-driven allocation.
- **Assistente AI**: single period axis + reactive context card; SSE streaming, 5 modes, gated web search, proactive memory. The data block carries the **full category→subcategory breakdown** (no top-5), spending by type and income by category, from a single pure aggregator. `claude-sonnet-5`, no prompt caching by design. Flag `NEXT_PUBLIC_ASSISTANT_AI_ENABLED`; blocked in demo.
- **Hall of Fame**: records and rankings with a period+category switcher.
- **Multi-theme**: 6 themes persisted in `userPreferences/{userId}` + localStorage; theme-aware charts via `useChartColors` (`--chart-1..5`).
- **Periodic emails**: monthly/quarterly/half-yearly/yearly + a **weekly budget email** (Sunday) — sent every week but with month-to-date and year-to-date figures, the horizon stated explicitly in every caption. Env: `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `ANTHROPIC_API_KEY`.
- **PDF export**: 7 configurable sections (Portfolio/Allocazione/Storico/Cashflow/Rendimenti/FIRE/Riepilogo) with a Total/Annual/Monthly filter. On Cashflow, **Export Totale** applies `cashflowHistoryStartYear` as a floor (the same setting as Cashflow/Storico, fallback `2025`); Storico/Rendimenti/FIRE stay unbounded. ## Known Issues (Active)
- **FX** depends on Frankfurter; 24h cache fallback (in-memory per process — cold serverless instances have no fallback). Pre-migration non-EUR assets without `currentPriceEur` show the native price as EUR until the first successful price update; a non-EUR asset with `autoUpdatePrice: false` never self-heals (the cron skips it) until it is re-saved with a price fetch.
- **Demo account**: requires manual Firebase setup — documented in README.md → Known Issues + env table (three `NEXT_PUBLIC_DEMO_*` vars).
- **Security review 2026-06-10**: all 8 findings closed. Caveat: `firebase-admin` pinned at `^13.6.0` (bumping to @14 pulls pure-ESM `jose@6` → `ERR_REQUIRE_ESM` on Vercel), so the 8 moderate `uuid` advisories stay open. ⚠️ `npm audit` (2026-08-13) also shows **5 HIGH advisories newer than the review** (nanoid, next, postcss, sharp, undici), all fixable via `npm audit fix` — bump not yet applied, pending a decision on the next/sharp upgrade risk.
- **Shared account setup**: prerequisites (whitelist, guest registers first, `firestore.rules` deployed) documented in SETUP.md → Step 5b; technical detail in AGENTS.md → *Shared Account*.
- **YOC/Current Yield** exclude sold assets (intended) and are scoped to the current holding via `holdingStartDate`, with a snapshot-derived fallback (`deriveHoldingStartDates`) for legacy rebuys without the stamp. The residual uncovered case is narrow: a sell+rebuy inside the same month, or a gap falling in months without `byAsset` — there the prior holding's dividends are INCLUDED against the new cost basis (never a regression, but an overstated YOC). AGENTS.md → *Dividends: coupon-expense timing & unified YOC*.
- **Rendimenti before `byAsset`: correct denominator, wrong numerator.** The `performanceBase.ts` backfill removes the basis step on historical months with no per-instrument breakdown (2023-01 → 2025-10 on the real account), but in those months the **variation** of the excluded assets stays inside the measured return: the home's revaluation and, systematically, the principal share of every mortgage instalment that raises equity. Not reconstructible — those snapshots have no per-instrument detail.
- **TWR monthly-bucket artifact (by design, not a formula bug)**: TWR neutralises an expense only if the net worth drop and the cash flow land in the **same month**. A large purchase paid from the portfolio is therefore neutral (the car in 03-04/2024 on the real account, ~21k: area and line fall together on the Evoluzione chart, return exact). **The trap is the opposite case**: recording a purchase both as an expense and as an **asset** leaves net worth unchanged while the cash flow drops, and the formula produces a phantom gain `(V + expense)/V − 1` — the same applies to every mortgage instalment if the property sits *inside* the basis. Record balances in the month they belong to. AGENTS.md → *History and Snapshot Baselines*.
- **The Assistant's cashflow figures changed on 2026-07-29** and already-saved threads are not regenerated (they are prose in Firestore, not recomputable values): an old conversation and a new one can report different numbers for the same month. Two distinct changes, with very different odds of showing up:
  - **`transactionCount` now excludes transfers** — it used to be a raw `expenses.length`, so it counted transfers that were already out of both spending and income ("Uscite −2.400 € over 47 transactions" with the transfers inside the 47 and outside the −2.400). Affects **anyone who uses transfers**, i.e. in practice always.
  - **Classification by `type` instead of by sign** — a refund recorded on a *spending* row with a positive amount now increases spending instead of landing in income (aligned with the Cashflow page and the emails, the same jump made on 2026-07-01). It does not affect anyone recording refunds as `type: 'income'`, which is the correct way: there, the old and new rules agree.
- **Cost-center colour slots 6-8 are still not theme-aware** (the contrast half was closed 2026-08-13): `useChartColors()` resolves `--chart-1..5` from the active theme and applies its luminance guard, then pads indices 5-9 from the **static** `CHART_COLORS`. Teal and orange there were darkened to their -600 steps (`#0D9488` 3.74:1, `#EA580C` 3.56:1), so every slot now clears the WCAG 1.4.11 3:1 floor — but slots 6-8 still follow no theme. Closing THAT is a product decision, not cleanup: clamping every slot into the guarded 0-4 band would make eight picker choices collapse onto five colours; the alternative is a `--chart-6..8` design pass across all 12 theme blocks (which would also unlock slots for trendFollowing/carry — `lib/constants/colors.ts:46`).
- **Cost center colours change tint on the first render after deploy** (intended, no backfill): `resolveCostCenterColorSlot` maps each legacy hex to the slot at the same position, so relative identity between centers is preserved and no two collide, but the tint now follows the active theme. The hex stays in Firestore until the owner re-saves that center from the dialog, which migrates it to a slot.
- **The three cost-center components have no test of their own** — neither Vitest nor Playwright; only the pure layer is covered (`costCenterUtils` + `costCenterColors`, 49 tests). Recorded as `Attenzione:` in `docs/critique-prompts.md` so the next redesign there knows it has no mechanical safety net.
- **Sign-colour CHIPS still sit below AA, and it is structural** (measured 2026-08-13, deliberately not fixed): plain sign text now clears 4.5:1 in all 24 combinations, but the canonical `bg-positive/10 text-positive` chip washes the background with the text's own hue, so contrast falls by construction — 15 of 24 combinations land at **3.34–4.40:1**. Neither obvious remedy works: making the dark chips pass would push `--destructive` to L 0.90–0.97 (a pale pink, not a red), and thinning the wash from `/10` to `/05` moves the worst case only 3.34 → 3.84. The correct fix is a separate text arm for chips, on the `--warning`/`--warning-foreground` model — a new token pair plus a change to DESIGN.md's Sign-Color Token Rule, which is hand-maintained. Judged disproportionate to a tenth of a point on a pattern verified legible by eye. AGENTS.md → *A tint of the text's own hue cannot reach AA behind that text*.
- **`MonthlyReturnsHeatmap` bypasses the sign tokens entirely** (`MonthlyReturnsHeatmap.tsx:28-35` uses raw `bg-red-600` / `bg-green-400` …), predating the token work and violating the Sign-Color Token Rule. Checked by eye after the 2026-08-13 darkening and it does **not** clash: those greens are cell fills while `--positive` is almost always text, and the two never sit adjacent. Consistency debt, not a visual defect.
- **Emails and the PDF export are a permanent token-drift surface**: both render outside the DOM, so CSS custom properties cannot reach them and every sign colour there is a literal hex, already out of sync — `#16a34a`/`#dc2626` in `monthlyEmailService.ts` AND `weeklyBudgetEmailService.ts`, `#10B981`/`#EF4444` in all 7 PDF section stylesheets. No token change will ever appear in them. Optional cleanup on the table: one shared sign-hex constants module would collapse the drift surface from ~9 files to 1.
- **A class held without a target entry is invisible to the balance score**: `toLegacyAllocationResult` iterates `Object.keys(targets)`, so e.g. a trendFollowing position with no configurable target never enters `byAssetClass` — its weight counts in neither `misallocationPct` nor `leverageGapPp`. Pre-existing, surfaced by the 2026-08-13 leverage-aware decomposition; AGENTS.md → Allocation Page.

## Design Context
Authoritative aesthetic spec: **DESIGN.md** (Apple + Linear/Vercel + Trade Republic; form-follows-function) — hand-maintained, **never regenerate it**; its YAML frontmatter is the normative layer read by the impeccable detector, `.impeccable/design.json` is only the extensions sidecar (its `narrative` is a verbatim mirror of DESIGN.md — never paraphrase it, and never let it carry a rule DESIGN.md lacks). Durable **product** truth — users, positioning, operating context, evidence on hand, accessibility posture — lives in **PRODUCT.md**, rebuilt on the current impeccable schema 2026-08-13; it deliberately holds no visual direction. Review prompts in `docs/{critique,audit}-prompts.md`. Users: self-directed Italian investors who want to understand their position quickly and with confidence. Principles: (1) data first, decoration never; (2) motion with a purpose; (3) density is a feature; (4) precision builds trust; (5) personality lives in the details.
