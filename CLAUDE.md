# CLAUDE.md - Net Worth Tracker (Lean)

## Project Overview
Next.js app for Italian investors: net worth, assets, cashflow, dividends, performance metrics and long-term planning on Firebase.

**This file is the INDEX**: "what it is + where it lives", nothing more. The *how* and the gotchas live in **AGENTS.md**; the aesthetic spec in **DESIGN.md**; env/emulators/Playwright in **SETUP.md**; users and positioning in **PRODUCT.md**. **Session rules and the guided-verification protocol are in [WORKFLOW.md](WORKFLOW.md); read it before starting.**

> **Language**: this file and AGENTS.md are in English. Italian is reserved for user-facing UI text. Page and feature names stay Italian, because they are the labels the product shows: Panoramica, Patrimonio, Cashflow, Analisi, Rendimenti, Allocazione, Storico, Previdenza, Impostazioni.

## Architecture Snapshot
- App Router; protected pages under `app/dashboard/*`.
- `lib/services/*` (service layer) → pure `lib/utils/*` → `lib/server/*` (server-only). React Query for caching/invalidation.
- Italy timezone helpers in `lib/utils/dateHelpers.ts`.
- Convention: extract logic into pure, tested `lib/utils`/`lib/services` functions; keep Firestore-coupled code thin.

## Key Features (Active)
- **Shared account (delegated access)**: a second user gets full co-owner read/write. **viewer** (logged-in) is decoupled from **owner** (`ownerId`) via `useActiveAccount()`. Grants in `account-access/{ownerUid}`; enforced in `firestore.rules` + `assertCanAccessAccount`. Switcher in both `Sidebar` and `SecondaryMenuDrawer`. AGENTS.md → *Shared Account / Delegated Access*.

- **Shell**: `PageHeader` (compact default, `legacy` on un-propagated pages) · `PageTabBar` under it (13px tabs, `aria-label` each) · `PageContainer width="wide"` for tile pages · Sidebar (eyebrow group labels, assistant as a route, 56px icon rail with 44px targets) · bottom pill + «Altro» drawer · `TileGridSkeleton`. DESIGN.md → §5 Compact Page Header / Tile Grid Skeleton / Navigation; AGENTS.md → *Navigation*.
- **Panoramica**: a rule-generated **verdict sentence** (`overviewNarrative.ts`) over a 12-column **tile grid** (`components/dashboard/overview/*`, shells in `components/ui/{tile,narrative-text,ranked-rows}.tsx`): Patrimonio (number, chips, ATH, sparkline + period, market digest) · Sintesi · Cashflow · Composizione · Costi · Obiettivo · Spese/Entrate per categoria · Asset principali — each tile one question, one reading line, then the figures. "Mercato:" digest = price effect per class, flows excluded. `useDashboardOverview()` → `GET /api/dashboard/overview`. AGENTS.md → *Panoramica and Dashboard Data Isolation*.
- **Patrimonio**: a verdict whose driver is an **instrument** (`patrimonioNarrative.ts`, fed by `topInstrumentMovers`) over six tiles — Patrimonio (the Panoramica's tile with a per-instrument market digest) · Liquidità (cash accounts, one per row) · Movimenti del mese (the ledger's buys/sells of the month) · Classi · Rendimento (unrealized G/P + best/worst from `topAssets`) · Strumenti (the management table with the tile's cadence: sortable, 2-click delete, Δ columns behind "Andamento", grouping by class, `--chart-3` tint on hand-priced rows; flat expandable rows below `desktop:`). **A Δ is a unit-price variation** (`assetPerformanceDeltas.ts`), never a value change. Every derived number lives in `patrimonioSummary.ts`. AGENTS.md → *Patrimonio*.
- **AssetDialog**: 2-step create (type → filtered form); edit reuses the same visibility logic and shows ledger qty/cost read-only. Class select for ETFs; optional `displayTicker`; `leverageRatio`; opt-in TER for `etf`/`commodity`/`crypto`.
- **Asset trade ledger (Registro operazioni)**: BUY/SELL/ADJUSTMENT per asset with optional cash settlement (net-worth-neutral). `TransactionDialog` + `AssetMovementsDialog` (P&L/return/XIRR, per-sell realized % and PMC-at-trade). Writes only through the Admin API; the asset doc stays authoritative via full replay. Feeds Rendimenti and Dividendi. AGENTS.md → *Asset Trade Ledger*.
- **Cashflow**: Tracciamento / Dividendi / Budget / (optional) Centri di Costo. **Transfers** are their own type, net-zero everywhere, with atomic two-balance reconciliation. **Tracciamento is a verdict over tiles** (`cashflowNarrative.ts` + `tracciamentoSummary.ts`): one period axis beside the verdict; Movimenti is the last tile and its toolbar narrows only the list. `ExpenseDialog` is 2-step on create. **Recurrence** (creation-only, Mensile|Annuale) materialises real future-dated rows sharing a `recurringParentId`; a saved entry's type is editable across all five types, never across the transfer boundary. AGENTS.md → *Cashflow › Tracciamento*, *Expense Sign Convention*, *Recurring Series*. The bottom-nav «+» FAB belongs to Tracciamento only.
- **Budget**: a verdict answering «sto rispettando il budget?» (`budgetNarrative.ts`) over five tiles — Tetto del mese (today's mark on the track, month-end at the app's ONE projection rule, trailing months against their own ceiling) · Categorie a rischio (projected overruns only) · Avvisi (crossed thresholds only) · Budget annuali (year-to-date) · Per categoria (the inventory) — plus an «Impostazioni» disclosure. **No period axis**; a fixed category never follows the pace; a budget already over is a fact, never a risk, and the page says WHEN it went over. **The ceiling is historicised by the daily cron** (`budgetHistory/{userId}/months/{YYYY-MM}`). AGENTS.md → *Cashflow › Budget*.
- **Centri di Costo**: optional 6th tab (`costCentersEnabled`); spending per project. **A verdict answering «quanto sta costando il progetto?» with NO period axis** (`costCenterNarrative.ts`) — a project's cost is its whole cost; every figure is «in totale» and a tile on another window names it — over three tiles (Totale with the trailing months stacked by center · Centri, the ranked inventory · Dormienti, unscoped last activity) plus an «Archiviati» disclosure; one center is the same shape (Costo with the ceiling's track · Per categoria · Ciclo di vita · Per sottocategoria with a session-only «al netto di» lens · Movimenti collegati) with the actions beside the verdict. The year-end projection is the app's ONE rule; a dormant or archived center has none. Delete UNLINKS expenses (count from the same query). AGENTS.md → *Centri di Costo*.
- **Expense CSV Import**: Impostazioni → Spese. Pure parse/validate/plan layer with a mandatory preview; shared `importBatchId` for one-tap undo. Category identity is **(name, type)**. `transfer` rows are rejected and balances never touched.
- **Analisi** (`/dashboard/analisi`): a verdict answering «dove vanno i soldi, e cosa è cambiato?» (`analisiNarrative.ts`) over the page's ONE three-mode axis (Anno corrente | Anno | Storico, plus a month; deep-linked) — Periodo (KPI trio with YoY pacing, monthly spending beside the previous year's) · Fuori scala (the month's anomalies, an Off-Axis tile absent without a month) · Spese maggiori · Spese/Entrate per categoria (FULL lists, clickable) · Scheda (the focused entity as a 12-column tile with `EntityDossier`; focus in the URL, survives period changes) · Flusso (**the only Sankey of the app**) — plus «Confronto annuale» and «Dettaglio» disclosures. ONE landing path (`handleEntitySelect`); keys by id, never by name. `cashflowHistoryStartYear` is shared (Cashflow/Storico/Assistant/overview) — do not rename it. AGENTS.md → *Analisi — a verdict over tiles* + *Expense Grouping* + *Sankey: node identity*.
- **Dividendi**: a verdict answering «quanto rendono i miei flussi?» (`dividendiNarrative.ts`) over six tiles — Incasso netto (hero, monthly bars, next payments) · Affidabilità (coverage strip + concentration) · Rendimento (YOC gross/net, current yield, DPS growth) · Chi paga di più · Per anno · Pagamenti (Tabella|Calendario) — plus a «Dettaglio» disclosure with the two server tables. **Received and announced are never one figure.** ONE period axis (Mese|Anno|12 mesi|Storico) beside the verdict; the instrument/type filters narrow only the list; the Rendimento tile is TTM and says so. `useDividendStats` is one range-free query per owner. **BTP Italia**: additive FOI coupon, next one provisional until announced. AGENTS.md → *Cashflow › Dividendi*.
- **Rendimenti**: a verdict answering «quanto rende il portafoglio, e rispetto a cosa?» (`performanceNarrative.ts`) over ONE axis (YTD | 1 anno | 3 anni | 5 anni | Storico; a custom range is a chip, never a slot) — Rendimento (TWR, or the period return below six months; growth-of-100 vs the 60/40) · Rischio (volatility, Sharpe, Sortino, max drawdown) · Consistenza (heatmap in the sign tokens) · Contributi (ledger vs cashflow) · Benchmark (six models, ALWAYS in EUR) · Plusvalenze realizzate (off the axis) · Capitale e mercato — plus a «Dettaglio» disclosure. **The subject names the window actually measured** and every gap is on its figure's basis. **Configurable basis** (pension funds and `excluded` assets out by default), named under the verdict. AGENTS.md → *Rendimenti — a verdict over tiles* + *measurement base* + *the measurement window*.
- **Benchmark comparison**: growth-of-100 + risk/return over 6 model portfolios; Sharpe/Sortino vs the period-average ECB rate. Env `FRED_API_KEY`.
- **Allocazione**: two-zone IA — Decision (`AllocationHero` + `RebalanceBandControl` + `ActionPlanner` Ribilancia/Versa/Preleva) then "Dettaglio" → composition + exposure. **`Asset.allocationRole` (`tradable`|`frozen`|`excluded`) is partitioned BEFORE `compareAllocations`** — which is why the total is smaller than net worth. **Leverage**: `leverageRatio` expands an asset into notional exposure; the plans solve a QP per instrument. AGENTS.md → *Allocation — `allocationRole` and where the filter must live* + *Allocation — the two plans and the leverage engine*.
- **Storico**: a verdict answering «come sono arrivato qui?» (`storicoNarrative.ts`) with **no period axis** — the growth since the first snapshot is WEALTH growth, contributions included and said so, never Rendimenti's CAGR — over five tiles: Evoluzione (value, three chips, the series with the notes as markers) · Raddoppi (Geometrico|Traguardi; ONE pace = the trailing-12-month monthly increase in €, deciding «accelera/rallenta» AND the projected next doubling) · Composizione (ONE card on one axis `Asset class | Liquidità`, 100%-stacked shares over a ranked breakdown with Δpp; Previdenza band from **`MonthlySnapshot.pension`**, exact from 2026-08, `pensionSource` says which) · Driver (savings vs market per year from `cashflowHistoryStartYear`, on the SAME months as the growth, with % and shares; last twelve months as bars) · **Valore per strumento** (one month from `MonthlySnapshot.byAsset`, never recomputed, each instrument's change split into price and quantity) — plus a «Dettaglio» disclosure. AGENTS.md → *Storico — a verdict over tiles*.
- **Fondo Pensione (Previdenza)**: manually-valued asset (`pensionFund`, value in `quantity` at **price 1**), `allocationRole: 'frozen'` by default. Three chapters — *Il fondo oggi*, *Anno fiscale {Y}*, *Storico {Y}* — the last two on a **year axis** that never touches the value or the return. Contributions in three natures (TFR/Volontario/Datoriale); only Volontario leaves a cash account. **Multi-person**: each fund links to a `FamilyMember`, and the tax recap runs once per member. **Fund return** keeps market TWR separate from the employer contribution (pay, not return) and from the IRPEF saving; an untrustworthy window replaces the number AND its decomposition with an explanation (`isPensionReturnMeasurable`). Integrated into Allocazione, Storico, Rendimenti and FIRE. AGENTS.md → *Fondo Pensione*.

What If re-runs `fireService` twice; Monte Carlo has a probability hero. **Pension bridge model**: with `respectPensionLockInFire` on, locked funds leave the spendable capital and re-enter at their unlock year across the whole page. ## Known Issues (Active)
- **FX** depends on Frankfurter with a 24h in-memory cache (no fallback on a cold instance). Pre-migration non-EUR assets without `currentPriceEur` show the native price as EUR until the first update; one with `autoUpdatePrice: false` never self-heals until re-saved.
- **Demo account** requires manual Firebase setup — README.md → Known Issues + the three `NEXT_PUBLIC_DEMO_*` vars.
- **Two deliberate dependency pins keep advisories open.** `firebase-admin` at `^13.6.0` (@14 pulls pure-ESM `jose@6` → `ERR_REQUIRE_ESM` on Vercel; 8 moderate `uuid` advisories stay) and `next` at `~16.2.12` (16.3.0 breaks Vercel at `onBuildComplete`; 2 HIGH libvips advisories via `sharp`, low exposure). **Unpin next and re-run `npm audit fix` once Vercel digests 16.3.x.**
- **Shared account setup** prerequisites (whitelist, guest registers first, rules deployed): SETUP.md → Step 5b.
- **YOC/Current Yield** exclude sold assets and are scoped to the current holding via `holdingStartDate`; a sell+rebuy inside one month, or a gap in months without `byAsset`, counts the prior holding's dividends against the new cost basis (an overstated YOC, never a regression).
- **Rendimenti before `byAsset`: correct denominator, wrong numerator** (2023-01 → 2025-10 on the real account): the basis step is removed, but the excluded assets' variation stays inside the measured return. Not reconstructible.
- **TWR monthly-bucket artifact (by design)**: an expense is neutralised only when the net-worth drop and the cash flow land in the same month; recording a purchase both as an expense and as an asset produces a phantom gain. Record balances in the month they belong to.
- **The Assistant's cashflow figures changed on 2026-07-29**; saved threads are prose and are not regenerated.
- **Chart slots 5-9 are not theme-aware** (`useChartColors()` pads from the static `CHART_COLORS`): Obbligazioni vs Trend Following ΔE ≈ 8 on Storico → Composizione. Same root cause as the cost-center colour slots. Fix = one `--chart-6..8` pass across the 12 theme blocks.
- **Centri di Costo**: no Playwright spec of its own; `CostCenterDialog` keeps its pre-redesign chrome; an annual ceiling has no crossing day (`crossedOn` is monthly only); «Al mese» divides by the calendar months since the first expense (an idle project reads as a lower monthly cost, by design); «in totale» counts rows dated up to today (a backdated row moves total and crossing day, a future row is «in calendario» and not summed); the subcategory lens and the movements window (25 + «Mostra altre») are per-center, session-only state.
- **Sign-colour CHIPS sit below AA, structurally** (`bg-positive/10 text-positive` washes the background with the text's hue: 15 of 24 combinations at 3.34–4.40:1; deliberately not fixed). `MonthlyReturnsHeatmap` fills its cells with the sign tokens at 30/55/85% (the figure is never printed in the cell, so the AA text floor does not apply). Emails and the PDF are a permanent token-drift surface (literal hexes outside the DOM).
- **A confirmed goal proposal can be confirmed again after a reload** (accepted for v1): reopening the thread re-parses the fenced block and a second press creates a SECOND goal.
- **Tracciamento**: the «Tabella» view renders `ExpenseTable` unchanged inside the Movimenti tile; the period slice uses `periodToRange` (browser local time) while the month buckets use the Italian calendar; the phone bar's controls are 36px; `TransactionFeed`/`CompactExpenseRow` carry two pre-existing `react-hooks` errors. A custom range has no previous period; a running year is compared with the same months of the previous year; the month-end projection exists only in the current month; the running month is drawn but never ranked. `components/dashboard/overview/NarrativeText.tsx` is an unused re-export (knip).
- **Budget**: `BudgetItemDialog` stays for create/edit (no inline editing); **the ceiling history starts with the first cron run after the deploy** (earlier months read against today's ceiling, «prima quello attuale»), a month's record is its LAST captured configuration; the crossing day comes from the EXPENSE DATES (a backdated row moves it), an annual budget has no crossing sentence; a budget with every threshold off and already exceeded shows only in Per categoria. `app/dashboard/cashflow/page.tsx` carries two pre-existing `react-hooks` findings (`loadOtherData`).
- **Dividendi**: the payments table dropped *Tax/Netto/Costo per azione*; the calendar day opens the day dialog instead of filtering; under «Mese» no month arrows, under «Anno» they stop at January/December; the 2-click delete keeps its 3 s auto-disarm; the list toolbar is rendered twice. The yield never follows the period (TTM on the current holding); the DPS running-year column is a partial sum; no `averageCost` → the tile becomes an explanation.
- **Analisi**: «Fuori scala» runs on ONE month and is absent otherwise (thresholds 25% / 50 € over a 6-month average, hardcoded); a month not started yet gets the «non è ancora iniziato» verdict; «Mostra tutte», the Confronto's comparison year and the Flusso toggles are session-only; the Scheda's transactions window is 25 + «Mostra altre»; the `EntityDossier` trend stays Recharts; `SavingsRateTrendSection`/`AndamentoStoricoSection` compute their series in the component (untested); the Sankey drops small slices on phones (declared); no Playwright spec covers «Anno» with a month; `main` scrolls, so a 390 `fullPage` screenshot stops at the viewport.
- **Storico**: no Playwright spec of its own; the pace and the next-doubling projection need the snapshot of EXACTLY twelve months earlier (a gap drops both clauses) and the pace verdict 24 months of history; the projection is linear and dropped beyond fifty years; the Driver shows only the years from `cashflowHistoryStartYear` (a year's savings = the cashflow rows between its baseline snapshot and its last one; untracked income lands in «mercato») and its bars only the last twelve CALENDAR months; the Lavoro net can be negative on a positive gross (taxes estimated on ALL latent gains); the Evoluzione Y axis prints full amounts under 10.000 € of span; the doubling confetti keeps literal hexes; `SnapshotSearchDialog`/`CreateManualSnapshotModal` keep their old chrome; at 768-1439 Raddoppi and Driver share a row while the skeleton stacks them.
- **Two pages are not yet propagated** (Allocazione, Previdenza; Centri di Costo is a tab and keeps its shape): they carry `PageHeader variant="legacy"` and a per-page skeleton.
- **Rendimenti**: no Playwright spec of its own; the six benchmark series + FX load on every visit (6h `staleTime`), only a FAILED FX route falls back to USD (the aside says so); Sharpe/Sortino use the settings' risk-free rate (the ECB period rate went with the old table); the payload's index-step `drawdownDuration`/`recoveryTime` are no longer displayed (the tiles read `resolveDrawdownStory`, calendar months); a 1-anno window without the current month's snapshot measures 11 months and says so; the rolling readings are built in `PerformanceDettaglio` (untested); `AIAnalysisDialog`/`CustomDateRangeDialog` keep their old chrome.
- **Patrimonio**: Δ columns are empty for pension funds and cash accounts by design; the Rendimento tile ranks only within the overview's `topAssets` (15 largest); «Movimenti del mese» reads the whole ledger and filters in memory (no `(userId, date)` index); the 2-click delete auto-disarms on a 3 s timer (kept on request); G/P against PMC compares a native-currency `averageCost` with the EUR value; `TaxCalculatorModal` simulates in the native price but labels €; the Compra/Vendi chips use the sign tokens for a trade direction. `AssetDialog.tsx` carries 7 pre-existing `react-hooks` errors.
- **The icon rail's 44px targets are measured at 1440 with a mouse**; no fixture covers a ≥1440px tablet in landscape.
- **The market digest's blind spots**: a position opened this month contributes 0 until next month; a pension fund counts only from `pensionReturnStartMonth`; hand-valued assets other than funds and real estate never show a market effect; real estate is measured gross of debt. Honest by construction.
- **A class held without a target entry is invisible to the balance score** (`toLegacyAllocationResult` iterates `Object.keys(targets)`).
