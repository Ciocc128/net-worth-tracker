# CLAUDE.md - Net Worth Tracker (Lean)

## Project Overview
Next.js app for Italian investors: net worth, assets, cashflow, dividends, performance metrics and long-term planning on Firebase.

**This file is the INDEX**: "what it is + where it lives", nothing more. The *how* and the gotchas live in **AGENTS.md**; the aesthetic spec in **DESIGN.md**; env/emulators/Playwright in **SETUP.md**; users and positioning in **PRODUCT.md**. **Session rules and the guided-verification protocol are in [WORKFLOW.md](WORKFLOW.md); read it before starting.**

> **Language**: this file and AGENTS.md are in English. Italian is reserved for user-facing UI text. Page and feature names stay Italian, because they are the labels the product shows: Panoramica, Patrimonio, Cashflow, Analisi, Rendimenti, Allocazione, Storico, Previdenza, Impostazioni.

## Architecture Snapshot
- App Router; protected pages under `app/dashboard/*`.
- `lib/services/*` (service layer) → pure `lib/utils/*` → `lib/server/*` (server-only). React Query for caching/invalidation.
- Italy timezone helpers in `lib/utils/dateHelpers.ts`.
- Convention: extract logic into pure, tested `lib/utils`/`lib/services` functions; keep Firestore-coupled code thin.

## Key Features (Active)
- **Shared account (delegated access)**: a second user gets full co-owner read/write. **viewer** (logged-in) is decoupled from **owner** (`ownerId`) via `useActiveAccount()`. Grants in `account-access/{ownerUid}`; enforced in `firestore.rules` + `assertCanAccessAccount`. Switcher in both `Sidebar` and `SecondaryMenuDrawer`. AGENTS.md → *Shared Account / Delegated Access*.
- **Demo mode**: public landing `app/page.tsx` + auto-login; `useDemoMode()` gates every mutation (compares `user.uid` to `NEXT_PUBLIC_DEMO_USER_ID`).
- **Panoramica**: asymmetric bento hero `[2fr_1fr]` (net worth + variation/ATH chip + sparkline + "Guidato da" digest) beside Sintesi Patrimoniale, then Cashflow KPIs and deferred charts. `useDashboardOverview()` → `GET /api/dashboard/overview`. AGENTS.md → *Panoramica and Dashboard Data Isolation*.
- **Patrimonio**: every asset type; hero twin of Panoramica; sortable table, 2-click delete, Δ columns behind "Andamento"; cash accounts in separate cards. Automatic prices (Yahoo / Borsa Italiana); `--chart-3` tint on manually-priced rows.
- **AssetDialog**: 2-step create (type → filtered form); edit reuses the same visibility logic and shows ledger qty/cost read-only. Class select for ETFs; optional `displayTicker`; `leverageRatio`; opt-in TER for `etf`/`commodity`/`crypto`.
- **Asset trade ledger (Registro operazioni)**: BUY/SELL/ADJUSTMENT per asset with optional cash settlement (net-worth-neutral). `TransactionDialog` + `AssetMovementsDialog` (P&L/return/XIRR, per-sell realized % and PMC-at-trade). Writes only through the Admin API; the asset doc stays authoritative via full replay. Feeds Rendimenti and Dividendi. AGENTS.md → *Asset Trade Ledger*.
- **Cashflow**: Tracciamento / Dividendi / Budget / (optional) Centri di Costo. **Transfers** are their own type, net-zero everywhere, with atomic two-balance reconciliation. Tracciamento is single-answer IA (`CashflowHero` → filter toolbar → `TransactionFeed`). `ExpenseDialog` is 2-step on create, single-step on edit. **Recurrence** (creation-only) covers the three spending types with a Mensile|Annuale cadence, materialised as real future-dated rows sharing a `recurringParentId`. A saved entry's **type is editable across all five types**; the batch re-typing paths refuse to cross the transfer boundary. AGENTS.md → *Expense Sign Convention and Type Changes* + *Recurring Series*.
- **Budget**: opt-in, overall ceiling + income budget + monthly|annual period, with Forecast / Insights / Alerts.
- **Centri di Costo**: optional 6th tab (`costCentersEnabled`); spending per project. **One period axis owned by the Panoramica and rendered in BOTH views**; ordered list, per-center budget/projection/lifecycle, per-subcategory breakdown with session-only exclusions. Budget/projection/chart keep their own window and name it. Delete UNLINKS expenses. AGENTS.md → *Centri di Costo*.
- **Expense CSV Import**: Impostazioni → Spese. Pure parse/validate/plan layer with a mandatory preview; shared `importBatchId` for one-tap undo. Category identity is **(name, type)**. `transfer` rows are rejected and balances never touched.
- **Analisi** (`/dashboard/analisi`): **entity-first**. Period selector (deep-linked) + entity search → KPI trio with YoY pacing → anomalies → Spese Maggiori → Sankey + drill-downs whose levels 2/3 lead with the **EntityDossier** (per-year table with signed Δ, each year row opening on the per-subcategory deltas; focus survives period changes and lives in the URL) → **Confronto** → "Dettaglio" collapsible. Every entity entry point lands through ONE path. **The only page with a Sankey.** NOTE `cashflowHistoryStartYear` is shared (Cashflow/Storico/Assistant/overview) — do not rename it. AGENTS.md → *Analisi — entity-first* + *Expense Grouping* + *Sankey: node identity*.
- **Dividendi**: in-memory period axis → net income hero + KPIs + reliability + payer leaderboard; Table/Calendar. `DividendStats` is a server-side ledger-based YOC/DPS/total-return block. **BTP Italia**: additive FOI coupon, next one provisional until announced.
- **Rendimenti**: single-answer IA — `PerformanceHero` (TWR + verdict + benchmark delta + drawdown chip) → consistency strip → collapsible `MetricSection`s → charts as "Andamento"/"Rischio". **Configurable basis** (pension funds and `excluded` assets out by default), stated under the hero. Drawdown runs on the TWR index. AGENTS.md → *Rendimenti — measurement base* + *the measurement window*.
- **Benchmark comparison**: growth-of-100 + risk/return over 6 model portfolios; Sharpe/Sortino vs the period-average ECB rate. Env `FRED_API_KEY`.
- **Allocazione**: two-zone IA — Decision (`AllocationHero` + `RebalanceBandControl` + `ActionPlanner` Ribilancia/Versa/Preleva) then "Dettaglio" → composition + exposure. **`Asset.allocationRole` (`tradable`|`frozen`|`excluded`) is partitioned BEFORE `compareAllocations`** — which is why the total is smaller than net worth. **Leverage**: `leverageRatio` expands an asset into notional exposure; the plans solve a QP per instrument. AGENTS.md → *Allocation — `allocationRole` and where the filter must live* + *Allocation — the two plans and the leverage engine*.
- **Storico**: hero (net worth + CAGR) → Evoluzione → Raddoppi → **Composizione** → Driver, plus **Valore per Strumento** (per-instrument read of one month from `MonthlySnapshot.byAsset`, never recomputed, + price/quantity attribution). **Composizione is ONE card on one axis** (`SegmentedPill` `Asset class | Liquidità` — two cuts of the same euro): a 100%-stacked area of shares only (no `€ | %` toggle; euro live in the tooltip and the list) over a ranked breakdown carrying value + share + Δpp vs 12 months, which **replaces the Recharts legend** at every breakpoint. Every `AssetClass` plus a Previdenza band and a **"Non attribuito"** residual; the stack closes at 100 by construction. AGENTS.md → *Recharts*.
- **Fondo Pensione (Previdenza)**: manually-valued asset (`pensionFund`, value in `quantity` at **price 1**), `allocationRole: 'frozen'` by default. Three chapters — *Il fondo oggi*, *Anno fiscale {Y}*, *Storico {Y}* — the last two on a **year axis** that never touches the value or the return. Contributions in three natures (TFR/Volontario/Datoriale); only Volontario leaves a cash account. **Multi-person**: each fund links to a `FamilyMember`, and the tax recap runs once per member. **Fund return** keeps market TWR separate from the employer contribution (pay, not return) and from the IRPEF saving; an untrustworthy window replaces the number AND its decomposition with an explanation (`isPensionReturnMeasurable`). Integrated into Allocazione, Storico, Rendimenti and FIRE. AGENTS.md → *Fondo Pensione*.
- **FIRE + Coast FIRE + What If + Monte Carlo**: single-answer Calcolatore FIRE (hero "FIRE proiettato nel {anno}, a {età}" + reddito passivo, basis row, Proiezione with a Scenari|Ventaglio pill, historical charts in a "Dettaglio" collapsible). **Coast FIRE is the same IA on a different question** — "posso smettere di versare?" — answered by the shortfall against `coastFireNumberToday`, with an inflow timeline naming the pension unlock and each state pension. What If re-runs `fireService` twice; Monte Carlo has a probability hero. **Pension bridge model**: with `respectPensionLockInFire` on, locked funds leave the spendable capital and re-enter at their unlock year across the whole page. AGENTS.md → *FIRE, What If and Goals*.
- **Goal-Based Investing**: trajectory-led (required monthly pace + projected date + verdict); optional goal-driven allocation. The Assistant reads these goals and can **propose** one, never write it. Pure math in `lib/utils/goalMath.ts` (SDK-free so the server can use it).
- **Assistente AI**: hero `[2fr_1fr]` (conversation | sticky companion), threads in a sheet, one period axis, SSE streaming, 5 modes, gated web search, proactive memory. The data block carries the **full category→subcategory breakdown** from a single pure aggregator. **Goals** are structured by a forced-tool-use Haiku call and evaluated against the current month after every turn and daily from the cron. **Goal-Based Investing** (a different thing) is a mandatory `goals` block; the assistant proposes via a fenced ```goal-proposal block and **only the user's Conferma writes**. Flag `NEXT_PUBLIC_ASSISTANT_AI_ENABLED`; blocked in demo. AGENTS.md → *Assistant*.
- **Hall of Fame**: records and rankings with a period+category switcher.
- **Multi-theme**: 6 themes in `userPreferences/{userId}` + localStorage; theme-aware charts via `useChartColors` (`--chart-1..5`).
- **Periodic emails**: monthly/quarterly/half-yearly/yearly (the AI comment reads the **same exhaustive bundle as the Assistant** over the email's window, plus precomputed market effect, comparisons, category deltas, Hall of Fame and budget alerts) + a **weekly budget email** (Sunday) whose figures are month-to-date and year-to-date, with the horizon stated in every caption. Env: `RESEND_API_KEY`, `RESEND_FROM_EMAIL`, `ANTHROPIC_API_KEY`.
- **PDF export**: 7 configurable sections with a Total/Annual/Monthly filter. On Cashflow, **Export Totale** applies `cashflowHistoryStartYear` as a floor (fallback `2025`); Storico/Rendimenti/FIRE stay unbounded.

## Known Issues (Active)
- **FX** depends on Frankfurter with a 24h in-memory cache, so a cold serverless instance has no fallback. Pre-migration non-EUR assets without `currentPriceEur` show the native price as EUR until the first successful update; one with `autoUpdatePrice: false` never self-heals (the cron skips it) until re-saved with a price fetch.
- **Demo account** requires manual Firebase setup — README.md → Known Issues + the three `NEXT_PUBLIC_DEMO_*` vars.
- **Two deliberate dependency pins keep advisories open.** `firebase-admin` at `^13.6.0` (@14 pulls pure-ESM `jose@6` → `ERR_REQUIRE_ESM` on Vercel), so 8 moderate `uuid` advisories stay. `next` at `~16.2.12`, the security-backport line: 16.3.0 breaks Vercel's deploy at `onBuildComplete`, and since `sharp` rides on next's tree the 2 HIGH libvips advisories stay (low exposure: Image Optimization is platform-managed). **Unpin next and re-run `npm audit fix` once Vercel's builder digests 16.3.x.**
- **Shared account setup** prerequisites (whitelist, guest registers first, rules deployed): SETUP.md → Step 5b.
- **YOC/Current Yield** exclude sold assets (intended) and are scoped to the current holding via `holdingStartDate`, with a snapshot-derived fallback for legacy rebuys. Residual uncovered case: a sell+rebuy inside one month, or a gap in months without `byAsset` — there the prior holding's dividends are included against the new cost basis (an overstated YOC, never a regression).
- **Rendimenti before `byAsset`: correct denominator, wrong numerator.** The `performanceBase.ts` backfill removes the basis step on historical months with no per-instrument breakdown, but the **variation** of the excluded assets stays inside the measured return there — the home's revaluation, and the principal share of every mortgage instalment. Not reconstructible.
- **TWR monthly-bucket artifact (by design)**: TWR neutralises an expense only when the net-worth drop and the cash flow land in the **same month**. The trap is recording a purchase both as an expense and as an **asset**: net worth is unchanged while the cash flow drops, producing a phantom gain `(V + expense)/V − 1`. Record balances in the month they belong to.
- **The Assistant's cashflow figures changed on 2026-07-29** and saved threads are not regenerated (they are prose in Firestore), so an old and a new conversation can report different numbers for the same month.
- **Chart slots 5-9 are not theme-aware**: `useChartColors()` resolves `--chart-1..5` from the theme and pads the rest from the static `CHART_COLORS`, which can repeat a theme hue. Measured on Storico → Composizione: Obbligazioni vs Trend Following are **ΔE ≈ 8** apart (effectively one teal), Azioni vs Carry both orange — visible only to a portfolio holding `trendFollowing`/`carry`. Same root cause as the cost-center colour slots (migrated without a backfill; legacy hexes stay in Firestore until a center is re-saved). The fix is one `--chart-6..8` pass across all 12 theme blocks.
- **The three cost-center components have no test of their own**, neither Vitest nor Playwright; only the pure layer is covered. Recorded in `docs/critique-prompts.md`.
- **Sign-colour CHIPS sit below AA and it is structural** (measured 2026-08-13, deliberately not fixed): plain sign text clears 4.5:1 everywhere, but `bg-positive/10 text-positive` washes the background with the text's own hue, so 15 of 24 combinations land at 3.34–4.40:1. Neither remedy works (dark chips push `--destructive` to pale pink; `/05` reaches only 3.84). The real fix is a separate text arm on the `--warning-foreground` model.
- **`MonthlyReturnsHeatmap` bypasses the sign tokens** (raw `bg-red-600`/`bg-green-400`). Checked by eye: those greens are cell fills and `--positive` is almost always text, so they never sit adjacent. Consistency debt, not a visual defect.
- **Emails and the PDF export are a permanent token-drift surface**: both render outside the DOM, so every sign colour there is a literal hex, already out of sync (`monthlyEmailService.ts`, `weeklyBudgetEmailService.ts`, all 7 PDF stylesheets). One shared sign-hex module would collapse ~9 drift files to 1.
- **A confirmed goal proposal can be confirmed again after a reload** (accepted for v1): the card's "creato" state is component state while the message is prose in Firestore, so reopening the thread re-parses the block and a second press creates a SECOND goal — visible and deletable, never a corrupted first one.
- **A class held without a target entry is invisible to the balance score**: `toLegacyAllocationResult` iterates `Object.keys(targets)`, so a position with no configurable target enters neither `misallocationPct` nor `leverageGapPp`.
