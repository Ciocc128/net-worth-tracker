# CLAUDE.md - Net Worth Tracker (Lean)

## Project Overview
Next.js app for Italian investors: net worth, assets, cashflow, dividends, performance metrics and long-term planning on Firebase.

**This file is the INDEX**: "what it is + where it lives", nothing more. The *how* and the gotchas live in **AGENTS.md**; the aesthetic spec in **DESIGN.md**; env/emulators/Playwright in **SETUP.md**; users and positioning in **PRODUCT.md**. **Session rules and the guided-verification protocol are in [WORKFLOW.md](WORKFLOW.md); read it before starting.**

> **Language**: this file and AGENTS.md are in English. Italian is reserved for user-facing UI text. Page and feature names stay Italian, because they are the labels the product shows: Panoramica, Patrimonio, Cashflow, Analisi, Rendimenti, Allocazione, Storico, Previdenza, Impostazioni.

## Architecture Snapshot
- App Router; protected pages under `app/dashboard/*`.
- `lib/services/*` (service layer) → pure `lib/utils/*` → `lib/server/*` (server-only). React Query for caching/invalidation.

## Known Issues (Active)
- **FX** depends on Frankfurter with a 24h in-memory cache, so a cold serverless instance has no fallback. Pre-migration non-EUR assets without `currentPriceEur` show the native price as EUR until the first successful update; one with `autoUpdatePrice: false` never self-heals (the cron skips it) until re-saved with a price fetch.
- **Demo account** requires manual Firebase setup — README.md → Known Issues + the three `NEXT_PUBLIC_DEMO_*` vars.
- **Two deliberate dependency pins keep advisories open.** `firebase-admin` at `^13.6.0` (@14 pulls pure-ESM `jose@6` → `ERR_REQUIRE_ESM` on Vercel), so 8 moderate `uuid` advisories stay. `next` at `~16.2.12`, the security-backport line: 16.3.0 breaks Vercel's deploy at `onBuildComplete`, and since `sharp` rides on next's tree the 2 HIGH libvips advisories stay (low exposure: Image Optimization is platform-managed). **Unpin next and re-run `npm audit fix` once Vercel's builder digests 16.3.x.**
- **Shared account setup** prerequisites (whitelist, guest registers first, rules deployed): SETUP.md → Step 5b.
- **YOC/Current Yield** exclude sold assets (intended) and are scoped to the current holding via `holdingStartDate`, with a snapshot-derived fallback for legacy rebuys. Residual uncovered case: a sell+rebuy inside one month, or a gap in months without `byAsset` — there the prior holding's dividends are included against the new cost basis (an overstated YOC, never a regression).
- **Rendimenti before `byAsset`: correct denominator, wrong numerator.** The `performanceBase.ts` backfill removes the basis step on historical months with no per-instrument breakdown (**2023-01 → 2025-10 on the real account**), but the **variation** of the excluded assets stays inside the measured return there — the home's revaluation, and the principal share of every mortgage instalment. Not reconstructible.
- **TWR monthly-bucket artifact (by design)**: TWR neutralises an expense only when the net-worth drop and the cash flow land in the **same month**. The trap is recording a purchase both as an expense and as an **asset**: net worth is unchanged while the cash flow drops, producing a phantom gain `(V + expense)/V − 1`. Record balances in the month they belong to.
- **The Assistant's cashflow figures changed on 2026-07-29** and saved threads are not regenerated (they are prose in Firestore), so an old and a new conversation can report different numbers for the same month.
- **Chart slots 5-9 are not theme-aware**: `useChartColors()` resolves `--chart-1..5` from the theme and pads the rest from the static `CHART_COLORS`, which can repeat a theme hue. Measured on Storico → Composizione: Obbligazioni vs Trend Following are **ΔE ≈ 8** apart (effectively one teal), Azioni vs Carry both orange — visible only to a portfolio holding `trendFollowing`/`carry`. Same root cause as the cost-center colour slots (migrated without a backfill; legacy hexes stay in Firestore until a center is re-saved). The fix is one `--chart-6..8` pass across all 12 theme blocks.
- **The three cost-center components have no test of their own**, neither Vitest nor Playwright; only the pure layer is covered — a redesign there has no mechanical safety net.
- **Sign-colour CHIPS sit below AA and it is structural** (measured 2026-08-13, deliberately not fixed): plain sign text clears 4.5:1 everywhere, but `bg-positive/10 text-positive` washes the background with the text's own hue, so 15 of 24 combinations land at 3.34–4.40:1. Neither remedy works (dark chips push `--destructive` to pale pink; `/05` reaches only 3.84). The real fix is a separate text arm on the `--warning-foreground` model.
- **`MonthlyReturnsHeatmap` bypasses the sign tokens** (raw `bg-red-600`/`bg-green-400`). Checked by eye: those greens are cell fills and `--positive` is almost always text, so they never sit adjacent. Consistency debt, not a visual defect.
- **Emails and the PDF export are a permanent token-drift surface**: both render outside the DOM, so every sign colour there is a literal hex, already out of sync (`monthlyEmailService.ts`, `weeklyBudgetEmailService.ts`, all 7 PDF stylesheets). One shared sign-hex module would collapse ~9 drift files to 1.
- **A confirmed goal proposal can be confirmed again after a reload** (accepted for v1): the card's "creato" state is component state while the message is prose in Firestore, so reopening the thread re-parses the block and a second press creates a SECOND goal — visible and deletable, never a corrupted first one.
- **Tracciamento keeps three debts the review surfaced**: the «Tabella» view renders `ExpenseTable` unchanged inside the Movimenti tile (bordered box, Sans amounts, `text-emerald`, chart-slot chips — a restyle of the power-user table is its own session); the period slice uses `periodToRange` (browser local time) while the month buckets use the Italian calendar, so a browser outside Europe/Rome can place a midnight row on different sides of a month boundary in the KPI and in the bar (pre-existing in the toolbar slice; the product's user is in Rome); the phone bar's period picker, «Filtri» and sort are 36px tall (the pre-existing `h-9` of `PeriodPicker`, shared with other pages). `TransactionFeed` and `CompactExpenseRow` carry two pre-existing `react-hooks` lint errors (`getLazyIcon` creates a component during render), untouched.
- **Tracciamento's comparisons stop where the data does**: a custom range has no previous period, so its verdict, KPIs and hero reading carry no delta; a year still running is compared with the same months of the previous year and clipped at today's month; the month-end projection exists only in the current month; the savings history names months without their year («aprile»), unambiguous only because the window is 12 months, and leaves the running month out of the ranking; the hero chart highlights a month only when the period IS a month. The Storybook stories of the old mobile cashflow page (`CashflowPage.stories`, `CashflowWidget.stories`) went with the components they rendered — the redesigned tab has no story. `components/dashboard/overview/NarrativeText.tsx` is an unused re-export knip already flagged before this session.
- **Five pages are not yet propagated** (Analisi, Rendimenti, Storico, Allocazione, Previdenza): they carry `PageHeader variant="legacy"` (30px title) next to the compact shell and keep a per-page skeleton that `TileGridSkeleton` replaces as each is redesigned. Rendimenti still prints `toFixed` percentages.
- **Patrimonio's Δ columns are empty for pension funds and cash accounts by design** (their quantity IS the value, there is no unit price to measure), and the Rendimento tile ranks returns only within the overview's `topAssets` (the 15 largest positions) — a small position with the best return is not named. The «Movimenti del mese» tile reads the owner's whole ledger and filters the month in memory: a month query would need a `(userId, date)` composite index that does not exist.
- **`AssetDialog.tsx` carries 7 pre-existing `react-hooks` lint errors** (set-state-in-effect, use-before-declare) untouched by the Patrimonio redesign — the file was only re-commented.
- **Patrimonio keeps three pre-existing debts the redesign surfaced**: the 2-click delete still auto-disarms on a 3 s timer (WCAG 2.2.1; kept «invariato» on request — the AGENTS pattern is pointerdown + Escape + blur); G/P against PMC compares a **native-currency** `averageCost` with the EUR value, so a USD position can read negative while up in dollars (pre-existing in `calculateUnrealizedGains`, now also behind the Rendimento ranking and `topAssets.returnPercent`); `TaxCalculatorModal` simulates in the asset's native price but labels the result in € (arithmetic untouched by the restyle). The Compra/Vendi chips of the Movimenti tile and of `AssetMovementsDialog` use the sign tokens for a trade direction, which the token rule reserves for gain/loss.
- **The icon rail's 44px targets are measured at 1440 with a mouse**; the only touch surface that can reach the collapsed sidebar is a ≥1440px tablet in landscape, which no fixture covers.
- **The market digest's blind spots**: a position opened this month contributes 0 until next month; a pension fund counts only from `pensionReturnStartMonth` (before it, contributions were unrecorded and its growth is not split); hand-valued assets other than funds and real estate (price 1) never show a market effect. Real estate is measured gross of debt so a mortgage instalment never reads as appreciation. Honest by construction.
- **A class held without a target entry is invisible to the balance score**: `toLegacyAllocationResult` iterates `Object.keys(targets)`, so a position with no configurable target enters neither `misallocationPct` nor `leverageGapPp`.
