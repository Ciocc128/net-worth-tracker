# CLAUDE.md - Net Worth Tracker (Lean)

## Project Overview
Next.js app for Italian investors: net worth, assets, cashflow, dividends, performance metrics and long-term planning on Firebase.

**This file is the INDEX.** Detailed conventions, patterns and gotchas live in **AGENTS.md**; the aesthetic spec is **DESIGN.md**; the local verification environment is in **SETUP.md**. **Session rules and the guided-verification protocol are in [WORKFLOW.md](WORKFLOW.md); read it before starting.** Keep entries here to "what it is + where it lives".

> **Language**: this file and AGENTS.md are written in English. Italian is reserved for user-facing UI text (see AGENTS.md → *Italian Localization*). Page and feature names stay in Italian throughout, because they are the labels the product actually shows: Panoramica, Patrimonio, Cashflow, Analisi, Rendimenti, Allocazione, Storico, Previdenza, Impostazioni.

## Key Features (Active)
- **Shared account (delegated access)**: a second user gets full co-owner read/write. **viewer** (logged-in user) decoupled from **owner** (`ownerId`) via `useActiveAccount()`. Grants in `account-access/{ownerUid}`; enforcement in `firestore.rules` + `assertCanAccessAccount`. Theme stays per-viewer. Switcher in both `Sidebar` and `SecondaryMenuDrawer` (portrait has no sidebar). AGENTS.md → *Shared Account / Delegated Access*.
- **Demo mode**: public landing `app/page.tsx` + auto-login; `useDemoMode()` gates every mutation (compares `user.uid` to `NEXT_PUBLIC_DEMO_USER_ID`).
- **Panoramica (Overview)**: asymmetric bento hero `[2fr_1fr]` — dominant net worth + variation/ATH chip + sparkline with period selector + "Guidato da" digest, beside Sintesi Patrimoniale (with goal progress). Then Cashflow KPIs and deferred charts. `useDashboardOverview()` → `GET /api/dashboard/overview`. AGENTS.md → *Panoramica and Dashboard Data Isolation*.
- **Patrimonio (Portfolio)**: every asset type; hero twin of Panoramica; sortable table, 2-click delete, Δ columns behind "Andamento"; cash accounts in separate cards. Automatic prices (Yahoo / Borsa Italiana); `--chart-3` tint on manually-priced rows via `requiresManualPricing`.
- **AssetDialog**: 2-step create (type → filtered form), edit reuses the same visibility logic. For ledger types it shows qty/average cost read-only (submit via `updateAssetMetadata`). Class select for ETFs; optional `displayTicker` alias; `leverageRatio` for leveraged ETFs; TER toggle for `etf`/`commodity`/`crypto` (ETC-wrapped instruments), opt-in and off by default.
- **Asset trade ledger (Registro operazioni)**: BUY/SELL/ADJUSTMENT per asset with optional cash settlement (net-worth-neutral). `TransactionDialog` (+ capital-gain preview) and `AssetMovementsDialog` (P&L/return/XIRR; each sell row also shows its own realized % and the PMC at the time of that sale). Writes only through the Admin API; the asset doc stays authoritative (full replay). Also feeds "Capitale investito"/"Plusvalenze" on Rendimenti and total return on Dividendi. AGENTS.md → *Asset Trade Ledger*.
- **Cashflow**: Tracciamento / Dividendi / Budget / (optional) Centri di Costo tabs. **Transfers** are a type of their own, net-zero everywhere, with atomic reconciliation of both balances. **Tracciamento** is single-answer IA: `CashflowHero` (net savings + one verdict + top-5 expenses) → filter toolbar → shared `TransactionFeed`. **`ExpenseDialog` is 2-step on create** (type picker → filtered form, `‹ Cambia tipo` to go back), single-step on edit. A saved entry's **type is editable across all five types, from the form** — cross-shape edits (transfer ↔ spesa/entrata) are reconciled from BOTH the old and new shape, while the batch re-typing paths (category type change, category/subcategory moves) refuse to cross the transfer boundary; the category re-attaches to the same-named one under the new type via `resolveEquivalentCategory`. AGENTS.md → *Expense Sign Convention and Type Changes*.
- **Budget**: opt-in, overall ceiling + income budget + monthly|annual period, with Forecast / Insights / Alerts. Pure `lib/utils/budgetUtils.ts`.
- **Cost Centers**: optional 6th tab (`costCentersEnabled`); spending per project. **One period axis (Mese/Anno/12 mesi/Sempre) owned by the Panoramica and rendered in BOTH views** — the Detail used to display a period it could not change. Ordered list where the bar encodes rank and the `%` encodes share of the period total; per-center budget/projection/lifecycle; per-subcategory breakdown with session-only exclusions that never touch the figures above. Budget, projection and chart keep their **own** window and each names it in its eyebrow, behind a chapter separator. Dormancy reads **unscoped** activity (`resolveLastActivityDate`), so the badge no longer follows the axis; a center's colour is a **theme slot**, never a hex; `isError` routes to `CostCenterErrorNotice` *before* the empty-state check; delete declares how many expenses it unlinks. AGENTS.md → *Centri di Costo*.
- **Expense CSV Import**: Impostazioni → Spese. Pure parse/validate/plan layer with a mandatory preview before any write; shared `importBatchId` for one-tap undo. Category identity is **(name, type)** — same-named categories of different types resolve/create side by side, untyped rows inherit the single namesake's type (ambiguous → rejected with the reason), same-name-same-type duplicates attach to the OLDEST document with a notice in the preview. `transfer` rows are rejected and balances are never touched.
- **Analisi** (`/dashboard/analisi`): **entity-first** (2026-08-14). Period selector (deep-linked) + entity search "Vai a categoria…" → KPI trio with YoY pacing rows → anomalies → Spese Maggiori → Sankey (flow view) + composition drill-downs whose levels 2/3 lead with the **EntityDossier** (per-year table with signed Δ — **ogni riga anno si apre sullo scostamento per sottocategoria** — run-rate, 24-month trend; multi-year blocks ignore the period axis; the focus survives period changes and lives in the URL as `?focusType&focusCat&focusSub`) → **Confronto** (promoted, arbitrary comparison year, per-category delta ranking with nuova/cessata) → "Dettaglio" collapsible (Andamento Storico in Storico mode + Andamento Risparmio). Every entity entry point (rows, search, anomaly chips, Confronto rows, Sankey nodes) lands through ONE path. **It is the only page with a Sankey**: "Anno Corrente / Anno / Storico" are not different views but a period selector on the same one. Categories and subcategories are keyed by **id** (never by name) and labelled with the type only where they genuinely collide on screen. NOTE `cashflowHistoryStartYear` is shared (Cashflow/Storico/Assistant/overview) — do not rename it. AGENTS.md → *Analisi — entity-first* + *Expense Grouping* + *Sankey: node identity*.
- **Dividendi (Dividends)**: Trade Republic-style IA with an in-memory period axis → net income hero + KPIs + reliability + payer leaderboard; Table/Calendar. `DividendStats` is a server-side YOC/DPS/total-return block, ledger-based (closed positions included with a "Chiusa" badge). **BTP Italia**: additive FOI coupon, the next one stays **provisional** until the user announces the rate.
- **Rendimenti (Performance)**: single-answer IA — `PerformanceHero` (dominant TWR + verdict + benchmark delta + drawdown chip + vital signs) → consistency strip → collapsible with the `MetricSection`s → charts clustered as "Andamento"/"Rischio". **Configurable basis** (pension funds and `excluded` assets are out by default), stated under the hero. **Drawdown on the TWR index**: Max Drawdown / Duration / Recovery / Underwater chain the same monthly returns as the heatmap. Window rules, IRR, thresholds and the Evoluzione chart: AGENTS.md → *Rendimenti — the measurement window*.
- **Benchmark comparison**: growth-of-100 + risk/return table over 6 model portfolios; Sharpe/Sortino against the period average of the ECB rate. **Env: `FRED_API_KEY`**.
- **Allocazione**: two-zone IA — Decision (`AllocationHero` + `RebalanceBandControl` + `ActionPlanner` Ribilancia/Versa/Preleva) then a "Dettaglio" divider → composition + exposure. **`Asset.allocationRole` (`tradable`|`frozen`|`excluded`) is partitioned BEFORE `compareAllocations`**: `frozen` stays in the denominator but never in a plan, `excluded` leaves the page entirely (which is why the total is smaller than net worth). **Leverage**: `leverageRatio` expands an asset into its notional exposure; the plans solve a QP per instrument. AGENTS.md → *Allocation — `allocationRole` and where the filter must live*.
- **Storico (History)**: hero (net worth + CAGR) → Evoluzione → Raddoppi → Composizione (dedicated "Previdenza" band) → Driver. Includes **Valore per Strumento**: a per-instrument read of one month from `MonthlySnapshot.byAsset` (never recomputed) + cross-month trend with price/quantity attribution.
- **Fondo Pensione (Previdenza)**: manually-valued asset (`pensionFund`, value held in `quantity` at **price 1**), `allocationRole: 'frozen'` by default. Three chapters: *Il fondo oggi* (hero `[2fr_1fr]` + return, decomposition in a collapsible), *Anno fiscale {Y}* and *Storico {Y}*, the last two governed by a **year axis** (`SegmentedPill`) that never touches the value or the return. Contributions in three natures (TFR/Volontario/Datoriale); only Volontario leaves a cash account. **Multi-person**: each fund links to a `FamilyMember` (RAL + eligibility) and the tax recap runs **once per member**, with the IRPEF saving as the dominant number of its card. **Fund return**: market TWR kept separate from the employer contribution (pay, not return) and from the IRPEF saving; when the window is suspicious or idle **both the number and its decomposition are replaced by an explanation** — one predicate, `isPensionReturnMeasurable`, read by the card and by the collapsible's guard. The `[2fr_1fr]` hero always has a companion (return, error, or `PensionReturnPendingCard`), every chapter degrades to `PensionErrorNotice` instead of zeros, and the copy agrees in number when more than one fund exists (`fundNoun`). Integrated into Allocazione (look-through), Storico (band), Rendimenti (outside the basis) and FIRE (bridge model). AGENTS.md → *Fondo Pensione*.
- **FIRE + Coast FIRE + What If + Monte Carlo**: single-answer Calcolatore FIRE — hero `[2fr_1fr]` "FIRE proiettato nel {anno}, a {età}" + reddito passivo, basis row, Proiezione with a Scenari|Ventaglio pill (Ventaglio = accumulation Monte Carlo fan from the real allocation, cumulative FIRE probability), historical charts demoted to a "Dettaglio" collapsible; **Coast FIRE is the same IA on a different question** — "posso smettere di versare?" answered by the shortfall (or surplus) against `coastFireNumberToday`, a companion projecting the patrimonio to the target age with no further contributions, an inflow timeline naming the pension unlock and each state pension, one Impostazioni collapsible, scenario cards and a Proiezione whose tooltip names the unlock step; What If simulates life events by re-running `fireService` twice; Monte Carlo with a probability hero. **Pension bridge model**: with `respectPensionLockInFire` on, locked pension funds (per-fund `unlockDate` override > RITA rule from `userAge`, single source `lib/utils/pensionUnlock.ts`) leave the spendable capital and re-enter at their unlock year — bridge FIRE number, step in every projection, capital inflows in Coast/What If/Monte Carlo. ## Known Issues (Active)
- **FX** depends on Frankfurter; 24h cache fallback (in-memory per process — cold serverless instances have no fallback). Pre-migration non-EUR assets without `currentPriceEur` show the native price as EUR until the first successful price update; a non-EUR asset with `autoUpdatePrice: false` never self-heals (the cron skips it) until it is re-saved with a price fetch.
- **Demo account**: requires manual Firebase setup — documented in README.md → Known Issues + env table (three `NEXT_PUBLIC_DEMO_*` vars).
- **Security review 2026-06-10**: all 8 findings closed. Two deliberate pins keep advisories open. (1) `firebase-admin` at `^13.6.0` — @14 pulls pure-ESM `jose@6` → `ERR_REQUIRE_ESM` on Vercel — so the 8 moderate `uuid` advisories stay. (2) **`next` at `~16.2.12`** (the security-backport line): 16.3.0 breaks Vercel's deploy at `onBuildComplete` (`ENOENT .next/next-server.js.nft.json`, emitted locally — a Next-16.3/Vercel-builder incompatibility, not our build), and since `sharp` rides on next's tree the 2 HIGH libvips advisories stay too (low real exposure: Vercel's Image Optimization is platform-managed). **Unpin next and re-run `npm audit fix` once Vercel's builder digests 16.3.x.**
- **Shared account setup**: prerequisites (whitelist, guest registers first, `firestore.rules` deployed) documented in SETUP.md → Step 5b; technical detail in AGENTS.md → *Shared Account / Delegated Access*.
- **YOC/Current Yield** exclude sold assets (intended) and are scoped to the current holding via `holdingStartDate`, with a snapshot-derived fallback (`deriveHoldingStartDates`) for legacy rebuys without the stamp. The residual uncovered case is narrow: a sell+rebuy inside the same month, or a gap falling in months without `byAsset` — there the prior holding's dividends are INCLUDED against the new cost basis (never a regression, but an overstated YOC). AGENTS.md → *Dividends and Coupons*.
- **Rendimenti before `byAsset`: correct denominator, wrong numerator.** The `performanceBase.ts` backfill removes the basis step on historical months with no per-instrument breakdown (2023-01 → 2025-10 on the real account), but in those months the **variation** of the excluded assets stays inside the measured return — the home's revaluation, and the principal share of every mortgage instalment. Not reconstructible.
- **TWR monthly-bucket artifact (by design, not a formula bug)**: TWR neutralises an expense only if the net worth drop and the cash flow land in the **same month**. A large purchase paid from the portfolio is therefore neutral (the car in 03-04/2024 on the real account, ~21k: area and line fall together on the Evoluzione chart, return exact). **The trap is the opposite case**: recording a purchase both as an expense and as an **asset** leaves net worth unchanged while the cash flow drops, and the formula produces a phantom gain `(V + expense)/V − 1` — the same applies to every mortgage instalment if the property sits *inside* the basis. Record balances in the month they belong to. AGENTS.md → *History and Snapshot Baselines*.
- **The Assistant's cashflow figures changed on 2026-07-29** and already-saved threads are not regenerated (they are prose in Firestore, not recomputable): an old conversation and a new one can report different numbers for the same month. Two changes: **`transactionCount` now excludes transfers** (it was a raw `expenses.length`, so transfers counted in the count while being out of both totals — affects anyone using transfers, i.e. always), and **classification by `type` instead of by sign** (a refund on a *spending* row with a positive amount now increases spending, aligned with the Cashflow page and the emails — no effect for anyone recording refunds as `type: 'income'`, which is the correct way).
- **Cost-center colours are theme SLOTS, migrated without a backfill**, with two open edges. **Slots 6-8 are still not theme-aware**: `useChartColors()` resolves `--chart-1..5` from the theme, then pads 5-9 from the static `CHART_COLORS`. Closing it is a product decision — clamping into the guarded 0-4 band would collapse eight picker choices onto five colours; the alternative is a `--chart-6..8` pass across all 12 theme blocks (which would also unlock trendFollowing/carry — `lib/constants/colors.ts:46`). And **each center's tint changed once on the first render after deploy** (intended): `resolveCostCenterColorSlot` maps every legacy hex to the slot at the same position, so relative identity is preserved and no two collide, but the tint now follows the theme. The hex stays in Firestore until the owner re-saves that center from the dialog.
- **The three cost-center components have no test of their own** — neither Vitest nor Playwright; only the pure layer is covered (`costCenterUtils` + `costCenterColors`, 49 tests). Recorded as `Attenzione:` in `docs/critique-prompts.md` so the next redesign there knows it has no mechanical safety net.
- **Sign-colour CHIPS still sit below AA, and it is structural** (measured 2026-08-13, deliberately not fixed): plain sign text clears 4.5:1 in all 24 combinations, but `bg-positive/10 text-positive` washes the background with the text's own hue, so 15 of 24 land at **3.34–4.40:1**. Neither remedy works — dark chips would push `--destructive` to a pale pink, and `/10` → `/05` moves the worst case only to 3.84. The real fix is a separate text arm for chips on the `--warning`/`--warning-foreground` model, disproportionate to a tenth of a point on a pattern verified legible by eye. AGENTS.md → *Color Theme System*.
- **`MonthlyReturnsHeatmap` bypasses the sign tokens entirely** (`MonthlyReturnsHeatmap.tsx:28-35`, raw `bg-red-600`/`bg-green-400`), predating the token work. Checked by eye after the 2026-08-13 darkening and it does not clash — those greens are cell fills, `--positive` is almost always text, and the two never sit adjacent. Consistency debt, not a visual defect.
- **Emails and the PDF export are a permanent token-drift surface**: both render outside the DOM, so CSS custom properties cannot reach them and every sign colour there is a literal hex, already out of sync — `#16a34a`/`#dc2626` in `monthlyEmailService.ts` AND `weeklyBudgetEmailService.ts`, `#10B981`/`#EF4444` in all 7 PDF section stylesheets. No token change will ever appear in them. Optional cleanup on the table: one shared sign-hex constants module would collapse the drift surface from ~9 files to 1.
- **A confirmed goal proposal can be confirmed again after a reload** (accepted for v1): the card's "creato" state lives in component state, while the message itself is prose in Firestore. Reopening the thread re-parses the ```goal-proposal block and shows Conferma again, so a second press creates a SECOND goal — visible and deletable, never a corrupted first one. Closing it means either persisting the outcome on the message or disabling the button when a goal with the same name exists.
- **The Calcolatore FIRE hero overflows the viewport at 390px** (measured 2026-08-18 while redesigning the Coast tab, deliberately not fixed — that work was scoped to Coast): the hero card renders **455px wide in a 390px viewport**, so the amounts on its right edge are clipped, and `document.scrollWidth` stays 0 because an ancestor clips it — which is why it never showed up as sideways scroll. Fix: `grid-cols-1` on the hero grid + `min-w-0` on both cards, as `CoastFireHero.tsx` now does. AGENTS.md → *Tailwind Breakpoints*.
- **A class held without a target entry is invisible to the balance score**: `toLegacyAllocationResult` iterates `Object.keys(targets)`, so e.g. a trendFollowing position with no configurable target never enters `byAssetClass` — its weight counts in neither `misallocationPct` nor `leverageGapPp`. Pre-existing, surfaced by the 2026-08-13 leverage-aware decomposition; AGENTS.md → *Allocation — the two plans and the leverage engine*.

## Design Context
Authoritative aesthetic spec: **DESIGN.md** (Apple + Linear/Vercel + Trade Republic; form-follows-function) — hand-maintained, **never regenerate it**; its YAML frontmatter is the normative layer read by the impeccable detector, `.impeccable/design.json` is only the extensions sidecar (mechanics in DESIGN.md → *How this file is read by tooling*). Durable **product** truth — users, positioning, operating context, evidence on hand, accessibility posture — lives in **PRODUCT.md**, rebuilt on the current impeccable schema 2026-08-13; it deliberately holds no visual direction. Review prompts in `docs/{critique,audit}-prompts.md`. Users: self-directed Italian investors who want to understand their position quickly and with confidence. Principles: (1) data first, decoration never; (2) motion with a purpose; (3) density is a feature; (4) precision builds trust; (5) personality lives in the details.
